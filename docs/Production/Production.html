The numbers don't always line up

In 5. Calibrated RCN Silos Stock the Batch No column holds a bin code (ANA-01) and the BIN No column holds a lot number (ANG26E09). The two headings are swapped.

In 14. Final Output Analysis the percentage columns are stored as fractions (0.68 for 68 %), while every other sheet stores them as whole numbers. Any import has to normalise this.

3. RCN Stock Report repeats Bags+Pallet Kg's, BIN No and BTM No twice in one header row, under two banded groups. Column names alone cannot identify a field.

How a batch is identified

BTM No → BIN No → Size grade → Lot No → Output grade → SKU

The BTM number arrives from procurement. The Lot number is created at cooking (step 8) and every sheet downstream is keyed on it instead.

That handover is the open question: some quality rows carry lot values like ANG26E01,E02 — two lots in one cell — which means one Lot is not cleanly one BTM. Whether BTMs merge into a Lot, and whether a Lot splits again, decides the whole schema.

Twelve quality checks, five workbooks

The chart draws Quality Checks 1 to 12. Only five workbooks carry them, and several checks share one sheet, separated by a Sampling Point value rather than by a separate file.

QC-1 → 2. Input RCN Quality · QC-5 → 13. Shelling Machine · QC-6 → 11. Shell Waste Sample · QC-7 → 12. Shelled Kernels · QC-8 and QC-11 → 14. Final Output · QC-9 and QC-12 → 10. Inprocess Packing.

QC-2, QC-3, QC-4 and QC-10 have no workbook at all.

Shell goes two ways at once

Shell is the plant's largest solid by-product and it has two quite different destinations.

Most is sold — 1,656 truckloads in 16. Shell Dispatch Tracker.

The rest is burned in the plant's own boiler — 645 daily lines in 21. Boiler Consumption — raising the steam that cooks the next batch. A by-product of step 10 is the fuel for step 8.

Where nothing is recorded

Cooling silos, 24 hours (step 9) — a full day of the process with no record of any kind.

Peeling (step 24) — an entire production stage with no workbook.

Humidification, husk winnowing, and the Colour Sorter / Dicing / Manual / Taiho finishing routes — all drawn on their chart, none of them captured.

These are the gaps to raise before any schema is fixed: is this on paper somewhere, or genuinely not captured at all?

Two packing lines, one module

Their chart draws the packing sequence twice — once for wholes coming straight off the ovens, once for graded kernels coming out of peeling.

But both write into the same eight columns of 9. Packing Process Report, separated only by the Grade value.

So this should be built as one packing module with a source field, not two — the same call that was made about warehouse receiving on the procurement side.

Four templates, still empty

17. Cooking Cycles Monitoring (16 columns), 18. Borma Loss Tally Sheet (17), 19. RCN Receipts Tally Sheet (9) and 20. Borma Machine Monitoring (13).

All four are laid out and formatted, all four have 1,652 pre-formatted blank rows, and none has a single value in it.

They are shown here in the rust ‘nothing recorded’ colour, because as far as data goes they are gaps — but they are the cheapest gaps to close, since the columns are already agreed.

What to ask before building

Can several BTMs be cooked into one Lot, and can one BTM split across Lots? The comma-separated lot values suggest yes — that decides whether traceability needs a junction table.

What are the exact formulas behind KOR, SHOT, FOT and the yield percentages? They are payment-affecting and currently only exist inside Excel formulas.

Is the cooling-silo rest period and the peeling stage recorded on paper, or genuinely not captured?

What tolerance on Dry Loss % (running at ~6 %) should flag a row as suspect?
